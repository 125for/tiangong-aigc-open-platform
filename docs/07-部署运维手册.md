# 天工 TianGong · 部署运维手册

文档版本：v1.0（2026-10-18）

## 1. 两种运行形态

| | local（开发/验收） | docker（类生产） |
| --- | --- | --- |
| 数据库 | H2 文件（`data/*.mv.db`） | MySQL 8（每服务独立 schema） |
| MQ | 进程内派发器 | RabbitMQ |
| 限流/nonce | JVM 内存 | Redis（分布式） |
| 指标 | Actuator JSON | Prometheus 抓取 + Grafana 面板 |
| 启动 | `scripts/dev-up.sh` | `docker compose up -d --build` |

## 2. local 模式

```bash
scripts/dev-up.sh start   # 编译 + 后台拉起 4 服务（端口 8080/8081/8082/8083）
scripts/svc.sh status|stop|start <gateway|account|billing|task>
# 自定义故障注入环境变量：
#   TG_ENGINE_FAIL_RATE (0~1, 默认0.1)   模拟推理失败率
#   TG_ENGINE_LATENCY_MS (默认2500)       模拟推理耗时
#   TG_TASK_TTL_SECONDS (默认120)         任务超时预算
#   TG_BILLING_FAILFAST (true 时 billing 拒绝服务，演示熔断)
```
日志：`logs/<service>.log`；H2 控制台：`http://localhost:808x/h2-console`（JDBC URL `jdbc:h2:file:./data/<svc>`，用户 sa/空密码，仅 local）。

## 3. docker 模式（类生产）

```bash
cd docker
docker compose up -d --build
# 首次自动：建库 schema、Flyway 迁移、种子商品、Prometheus 抓取配置
docker compose ps && docker compose logs -f tg-task
```
服务配置经环境变量注入（compose 已给齐），关键项：

| 环境变量 | 说明 | 默认 |
| --- | --- | --- |
| SPRING_PROFILES_ACTIVE | local / docker | local |
| TG_JWT_SECRET | JWT 签名密钥(≥32B) | dev-only 默认值（生产必须覆盖） |
| TG_AES_KEY | AppSecret 加密主密钥(32B Base64) | dev-only 默认值 |
| TG_INTERNAL_TOKEN | 服务间调用令牌 | dev-only 默认值 |
| TG_CHANNEL_HMAC_KEY | 支付回调验签密钥 | dev-only 默认值 |
| MYSQL_HOST/REDIS_HOST/RABBIT_HOST | 基础设施地址 | mysql/redis/rabbit |

> 生产 checklist：所有密钥走 KMS/Secret Manager；H2 仅限本地；MySQL 开 GTID+备份；网关前置 LB/HTTPS。

## 4. 监控与告警

- 健康检查：`GET {svc}/actuator/health`（含 db/mq 组件状态），K8s readiness/liveness 直接可用；
- 指标：`/actuator/prometheus`。核心告警项（Prometheus 规则随 compose 提供）：
  - `resilience4j_circuitbreaker_state{state="open"}` 持续 1m → 告警；
  - outbox `tg_outbox_pending_count > 100` 5m → 告警（投递积压）；
  - `http_server_requests_seconds{uri="/api/v1/tasks"}[5m]` P99 > 1s → 告警；
  - Webhook FAILED 新增 → 工单。
- 日志：结构化单行 JSON 风格字段（ts/level/traceId/logger/msg），生产接 ELK/Loki（路线图）。

## 5. 发布与回滚

- 版本：镜像 tag = git sha；Flyway 只增不改（已发布迁移文件不可修改）；
- 发布顺序：先启新实例（readiness 通过）再摘旧实例（优雅停机 30s）；DB 迁移先行且向后兼容（新增列可空/带默认）；
- 回滚：应用回滚到上一镜像；**DB 不自动回滚**——靠兼容式迁移保证旧代码可跑（面试高频点）。

## 6. 常见故障排查（Runbook）

| 症状 | 排查 |
| --- | --- |
| 提交任务 503 D0101 | billing 是否存活 → 熔断器状态 `task/actuator/circuitbreakers` → 20s 半开自动恢复 |
| 回调 400 B0202 | 渠道 HMAC 密钥是否一致；签名字符串拼接顺序见 docs/04 §1.2 |
| 任务卡 PENDING | outbox 积压？`/actuator/metrics/tg_outbox_pending_count`；MQ 是否可达 |
| 余额对不上 | 按 docs/03 §5 用 ledger 重放对账；查 holds 未终结单 |
| 429 过多 | IP 桶默认值 vs AppKey 配额（应用详情可查、可调） |
