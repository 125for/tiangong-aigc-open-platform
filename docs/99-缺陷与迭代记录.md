# 天工 TianGong · 缺陷与迭代记录

本文件记录开发过程中的关键踩坑、修复与「实现 vs 文档」差异。**这是面试讲深度的最好素材**：每个条目都是真实工程问题 → 根因 → 修复 → 沉淀。

## 2026-10-18 · M1 交付基线

### D-01 家族撤销被事务回滚吞掉（安全缺陷级踩坑）
- 现象：检测到 RefreshToken 重放后，撤销整个令牌家族的 UPDATE 并未生效，家族内新 token 仍可用。
- 根因：撤销 UPDATE 与「抛出 401 异常」在同一个 `@Transactional` 方法内，异常触发整个事务回滚，撤销被一并回滚。
- 修复：`RefreshTokenRevoker` 独立组件 + `REQUIRES_NEW`，安全动作先于拒绝提交（tg-account/service/RefreshTokenRevoker.java）。
- 沉淀：**"写操作 + 拒绝请求"必须拆事务**；Spring 声明式事务的回滚边界包含方法内一切写。

### D-02 支付回调金额校验恒为「不相等」
- 现象：`回调金额 2900 ≠ 订单金额 2900`——数值相同却判不等。
- 根因：两个 `Integer`（128~127 缓存之外）用 `!=` 比较，比较的是对象引用。
- 修复：`intValue()` 显式拆箱比较（PaymentService）。
- 沉淀：包装类型比较必须 equals/拆箱；同类问题还有 `Long`、`Boolean`。

### D-03 单线程调度器被慢任务饿死（可用性缺陷级踩坑）
- 现象：任务超时扫描器长时间不执行，任务卡 RUNNING；手动调用却正常。
- 根因：Spring 默认 `TaskScheduler` 线程池 = 1。测试中派发器同步执行 Worker（模拟推理 sleep 15s），把唯一调度线程占满，超时扫描/Outbox/Webhook 全部停摆。
- 修复：`spring.task.scheduling.pool.size=4`；生产上进一步原则：**调度线程里永远不做慢 IO，慢活丢给业务线程池**。
- 沉淀：定时任务全链路必须排查线程模型，"定时器没跑"九成是"被别人堵了"。

### D-04 `@Modifying` 更新在自调用场景没有事务
- 现象：Outbox 中继轮询到了消息，`advance`（UPDATE）静默失败，消息永远 PENDING。
- 根因：中继 `relay()` 调用**同类**的 `@Transactional relayOnce()`，自调用绕过代理；@Modifying 语句无事务可用直接抛 TransactionRequiredException 被外层 catch 吞掉。
- 修复：把 `@Transactional` 下沉到 Repository 方法（自足式事务），不依赖调用方是否有事务。
- 沉淀：自调用失效是 Spring AOP 两大经典陷阱之一（另一个是内部 `new`）。

### D-05 H2/MySQL 方言差异
- `CHAR(64)` 列在 H2 报 `character vs varchar` 校验失败 → 统一 `VARCHAR`；
- `family_id` 首次插入必须为 NULL（族号=自增 id 回填）→ 列改可空；
- H2 以 `MODE=MySQL;DATABASE_TO_LOWER=TRUE` 运行 MySQL 方言迁移，一套 DDL 两库通用。

### D-06 surefire 不执行 `*IT` 命名
- 现象：模块 BUILD SUCCESS 但集成测试 0 执行。
- 根因：surefire 默认只匹配 `*Test`；`*IT` 是 failsafe 约定。
- 修复：类名统一 `*Test`（完整验收门禁见 docs/06）。

### D-07 provided 依赖不传递
- tg-common 被 MVC 服务与 WebFlux 网关共用，不能传递引入 starter-web（会导致网关双栈冲突）；`provided` 依赖的传递依赖也不可见。
- 方案：common 以细粒度 provided（spring-web/webmvc/tx/servlet-api/jackson/slf4j）声明 API，服务自带实现；网关排除 spring-webmvc。

### D-08 健康检查拖垮「零依赖」local 模式
- 现象：local 模式（无 Rabbit/Redis）服务 health 返回 503，dev-up 健康等待超时。
- 根因：amqp/redis starter 自动注册的健康指示器尝试连接不存在的中间件。
- 修复：`management.health.rabbit/redis.enabled=false`（local），docker profile 恢复。
- 沉淀：健康检查要区分「自身存活」与「依赖可用」，liveness 不应包含易变依赖。

### D-09 任务回调地址跨服务传递
- 任务服务不知道应用配置的 callback_url（存于 account）。方案：网关 AppKey 验签时已取得应用信息，顺手把 callback_url（URL 编码）注入 `X-App-Callback-Url`，同时列入网关无条件剥离头清单（防直连伪造）。请求级 callbackUrl 优先于应用级。
