# 天工 TianGong · 测试方案与验收手册

文档版本：v1.0（2026-10-18）

## 1. 测试策略

| 层次 | 工具 | 覆盖 | 运行方式 |
| --- | --- | --- | --- |
| 单元测试 | JUnit 5 + Mockito | 状态机、计价、签名算法、令牌服务、账务计算 | `mvn test`（零外部依赖，H2 内存） |
| 集成测试（切片） | `@SpringBootTest` + MockMvc | 注册登录全流程、支付回调幂等、预扣并发、任务提交幂等、Outbox 状态 | `mvn verify` |
| 端到端冒烟 | `scripts/smoke-test.sh`（Bash+curl） | 真实拉起 4 进程，走通 7 大验收场景 | 见 §3 |
| 压测（M3） | k6（`scripts/load-test.js`） | 提交链路 QPS/P99 | docker profile |

断言原则：**每个容错机制至少一条自动化用例**（对应 docs/05 的 F1~F14 中可自动化项），其余通过冒烟脚本人工触发观察。

## 3. 端到端手工验收（local 模式，一条命令准备）

```bash
cd tiangong
scripts/dev-up.sh          # 编译并后台拉起 gateway/account/billing/task（local profile）
tail -f logs/*.log         # 观察日志（另开终端）
```

### 场景 V1 全流程主链路（约 2 分钟）
```bash
scripts/smoke-test.sh
```
脚本自动执行并在每步输出 ✔/✘ 与关键断言：
1. 注册随机用户 → 登录拿 JWT；
2. 创建应用 → 记录 AppKey/AppSecret，配置 callback_url 指向任务服务测试 Sink；
3. 查询套餐 → 下单（starter_pro）→ 模拟支付回调 → 断言积分到账（balance == monthly_credits）；
4. 签名提交任务 TEXT_TO_IMAGE → 202 PENDING；
5. 轮询任务详情直到 SUCCEEDED（模拟推理 2~6s）→ 断言 result_url 存在、balance 减少恰为定价；
6. 查询 Webhook Sink → 断言收到终态通知且 taskNo 匹配；
7. 查询账务流水 → 断言 GRANT(订阅)/HOLD/SETTLE 三笔齐全。
**通过标准**：7 步全部 ✔，服务日志无 ERROR（预期外）。

### 场景 V2 幂等与重复通知
```bash
# 支付回调重放（脚本内置 --replay-pay 参数）
scripts/smoke-test.sh --replay-pay     # 同一回调再发 3 次 → delivered:false，balance 不变
# 任务提交重放
scripts/smoke-test.sh --replay-task    # 同 Idempotency-Key 再提交 → 返回同一 taskNo，任务数不增
```

### 场景 V3 故障注入（容错演示）
```bash
# a) 推理全失败 → 自动退款
TG_ENGINE_FAIL_RATE=1.0 scripts/dev-up.sh   # 以 100% 失败率重启
scripts/smoke-test.sh --expect-task-failed  # 断言 FAILED 且 REFUND 流水金额 == 定价

# b) billing 宕机 → 熔断快速失败；恢复 → 闭合
docker_pid_stop tg-billing （local 模式：scripts/svc.sh stop billing）
scripts/smoke-test.sh --task-while-billing-down   # 断言 503/D0101 且无任务落库
scripts/svc.sh start billing && sleep 20           # 等熔断半开
scripts/smoke-test.sh                             # 恢复正常

# c) 任务超时 → TIMEOUT+退款
TG_TASK_TTL_SECONDS=2 TG_ENGINE_LATENCY_MS=8000 scripts/dev-up.sh
scripts/smoke-test.sh --expect-task-timeout
```

- [ ] Swagger UI（:8081~:8083 /swagger-ui.html）可浏览并调试全部接口；
- [ ] 停任一服务再恢复，无人工数据修复，最终状态正确；
- [ ] 日志均带 traceId，跨服务可串联一次请求。
