## 3. 面试叙事（STAR 模板）

- **S**：自选 AIGC 开放平台场景（开放 API + 按调用积分计费）；核心难点是「长耗时不稳定推理 + 资金敏感计费 + 开放 API 安全」三者叠加下的正确性；
- **T**：独立完成后端全链路：账号/应用密钥、订阅与积分账务、异步任务调度、开放网关；
- **A**：
  1. 幂等三层设计（API 幂等键回放 / 业务唯一约束 / 状态机乐观锁），支付回调重放与任务重复提交实测零副作用；
  2. 预扣—结算—退款跨服务最终一致，billing 熔断时提交快速失败、退款转 Outbox 延迟补偿，资金不降级不伪造；
  3. 本地消息表替代事务消息，Worker/中继/Webhook 全部带退避重试与死信出口，任意进程 kill -9 后零人工修复自愈；
  4. 网关 HMAC 签名防重放（时间窗+nonce）+ 双维令牌桶限流 + Resilience4j 熔断，故障可配置注入、可观测；
- **R**：40+ 自动化用例全绿（含 20 并发抢余额账务一致性）、7 场景冒烟脚本一键验收、Compose 一键类生产部署。

**高频追问准备**（建议每轮迭代时口头复述一遍）：
1. 为什么幂等用 DB 唯一约束而不是 Redis SETNX / 先查后插？
2. 乐观锁冲突热点账户怎么办？（重试→分桶→队列化串行）
3. Outbox 和 RocketMQ 事务消息的差异与取舍？
4. 熔断打开期间退款请求怎么保证不丢？（异步补偿队列，最终一致）
5. 为什么 AccessToken 不做黑名单？什么场景必须做？
6. 状态机为什么用 DB version 而不是分布式锁？
7. 网关验签为何用 HMAC 而非 OAuth2 client credentials？各自适用面？
8. 任务超时为什么用扫描而不是纯 TTL+死信？两者怎么组合？
9. H2 与 MySQL 方言差异踩过什么坑？（TIMESTAMP 精度/自增）
10. 如果推理换成真实 GPU 集群，架构怎么演进？（队列分优先级、配额隔离、水位控制）
